Fases del Proceso de Desarrollo de Software

Inicio

1. Contacto Inicial con el Cliente

En esta fase se establece el primer acercamiento con el cliente. El objetivo principal es conocer su necesidad, entender el contexto del proyecto y recopilar información preliminar que permitirá orientar las siguientes etapas del desarrollo.

Realizar la primera reunión

La primera reunión sirve para presentarse, comprender la idea general del proyecto y determinar qué problema necesita ser resuelto. Se recopila información base y se evalúa la viabilidad inicial.
En este caso el contacto fue realizado con el dueño de una importadora de repuestos para moto, se hizo la primera reunion en presencial para recopilar los datos necesarios para el desarrollo de la solucion a su problema.

Escuchar qué necesita y por qué

Es fundamental comprender no solo lo que el cliente quiere, sino también el motivo detrás de su necesidad. Esto permite diseñar una solución que realmente aporte valor al negocio o al usuario final.
El cliente en este punto cuenta con un sistema poco fiable de registro de deudores que se basa en un archivo excel, el cual se almacena unicamente en la computadora utilizada en el establecimiento (tiene un respaldo en drive que se guarda cada que se realizan cambios) si bien es una solucion, no es una solucion practica para para muchas situaciones.

Hacer preguntas para entender el problema

Se realizan preguntas claras y específicas para obtener detalles adicionales: quién usará el sistema, qué tareas debe automatizar, qué problemas actuales existen y qué espera el cliente de la solución.
Despues de esa serie de preguntas tenemos muy claro el cuantas personas tendran acceso a modificaciones, visualizaciones, y actualizacion de datos dentro de la solucion por proponer.

2. Levantamiento de Requisitos

Esta fase consiste en recopilar y documentar toda la información necesaria para definir el comportamiento del sistema. Se describen las funciones, usuarios, restricciones y todos los elementos que formarán la base del proyecto.

Identificar usuarios del sistema

Se determina quiénes interactuarán con el sistema, clasificándolos según su rol: administrador, usuario general, supervisor, etc. Esto permite diseñar funciones adaptadas a cada tipo de usuario.

Definir funciones principales y secundarias

Las funciones principales son aquellas esenciales para el propósito del sistema; las secundarias complementan y facilitan la experiencia del usuario. Ambas deben ser documentadas con claridad.
En este punto tenemos claro que el cliente necesita que en el sistema permita:

  • Tener una herarquia de roles
  • Iniciar sesion para un acceso seguro
  • Visualizar una lista con los deudores que maneja su establecimiento
  • Visualizar la deuda que tiene cada deudor
  • Permitir buscar a un deudor especifico
  • Visualizar Nombres y detalles del cliente(Ciudad, monto de deuda)
  • Permitir restar el valor de una deuda agregando un pago
  • Cerrar sesion

Especificar pantallas necesarias

Se enumeran todas las pantallas o vistas necesarias, como formularios, paneles de control, menús, reportes o perfiles de usuario.

Determinar qué datos se guardarán

Se especifican los datos que el sistema almacenará, como información de usuarios, registros, transacciones, archivos, entre otros.
En este caso los datos a considerar en este apartados serian:

  • Nombres de deudores
  • Ciudad de deudores
  • Monto de deudores
  • Monto de deuda de cada deudor

Establecer restricciones

Se definen reglas obligatorias como permisos, accesos, límites del sistema, validaciones y requerimientos técnicos.

3. Análisis del Problema

En esta fase se estudia a profundidad la información recolectada para entender exactamente cómo debe funcionar el sistema y cómo debe procesar los datos. Se identifican procesos clave y la interacción entre ellos.

Definir procesos y reglas de negocio

Se describen paso a paso los procesos internos del sistema, así como las reglas que determinan su funcionamiento. Estas reglas deben estar alineadas a los objetivos del cliente.

Crear diagramas de flujo

Los diagramas de flujo permiten visualizar la lógica del sistema y cómo fluye la información entre procesos, ayudando a detectar problemas antes del desarrollo.

Desarrollar casos de uso

Los casos de uso describen cómo interactúan los usuarios con el sistema paso a paso. Esta herramienta es clave para asegurar que todas las funciones necesarias sean contempladas.

4. Diseño de la Solución

En esta fase se crea la estructura visual y técnica del sistema. Se diseñan pantallas, prototipos y la arquitectura que dará soporte al software.

Crear Wireframes (Bocetos)

Los wireframes son bocetos simples que muestran la distribución de elementos en cada pantalla. Ayudan a visualizar la idea antes de hacer diseños detallados.

Diseñar prototipos en Figma

En Figma se desarrollan prototipos interactivos que representan cómo se verá y se comportará la aplicación. Esto permite validar la experiencia de usuario antes de programar.

Definir arquitectura del sistema

La arquitectura define cómo se organizarán los módulos, bases de datos, APIs y componentes tecnológicos que permitirán el correcto funcionamiento del sistema.
