¿Qué es la Programación Orientada a Objetos?

La Programación Orientada a Objetos (POO) es un paradigma de programación que organiza el código en torno a entidades llamadas objetos, los cuales combinan datos y comportamientos. Este enfoque permite crear sistemas más ordenados, reutilizables y fáciles de mantener. Su principal objetivo es modelar elementos del mundo real para facilitar el desarrollo de software de manera clara y estructurada.

  • Las clases actúan como plantillas o moldes que describen cómo serán los objetos.
  • Los objetos son instancias reales que contienen datos (atributos) y acciones (métodos).
  • La POO permite trabajar de manera modular dividiendo programas grandes en piezas más pequeñas.
  • Los cuatro pilares de la POO ayudan a crear software mantenible, seguro y flexible.
  • Gracias a la POO se pueden reutilizar estructuras completas mediante herencia y polimorfismo.

Los 4 Pilares de la Programación Orientada a Objetos

1. Encapsulamiento

El encapsulamiento consiste en proteger los datos de un objeto evitando que sean modificados directamente desde afuera. Esto se logra usando modificadores de acceso como private y métodos llamados getters y setters. Gracias a este principio, se controla quién puede interactuar con la información y cómo puede hacerlo, garantizando mayor seguridad y orden en el código.

Ejemplo (Kotlin):

class Persona {
    private var nombre: String = ""

    fun setNombre(n: String) {
        nombre = n
    }

    fun getNombre(): String {
        return nombre
    }
}

En este ejemplo la clase Persona posee un atributo privado llamado "nombre", lo que significa que no puede accederse directamente desde fuera de la clase. Para modificarlo o consultarlo se utilizan las funciones setNombre() y getNombre(). La primera recibe un parámetro "n" de tipo String y asigna ese valor al atributo interno, mientras que la segunda devuelve el nombre almacenado.

2. Herencia

La herencia permite crear clases nuevas basadas en clases existentes. Esto facilita la reutilización de código y permite construir jerarquías de clases donde las clases hijas heredan atributos y métodos de la clase padre. También permite extender funcionalidades sin reescribir código desde cero.

Ejemplo (Kotlin):

open class Animal {
    fun comer() {
        println("El animal está comiendo")
    }
}

class Perro : Animal() {
    fun ladrar() {
        println("El perro ladra")
    }
}

En este ejemplo la clase Animal se declara como open, lo que significa que puede ser utilizada como clase padre en un proceso de herencia. Dentro de ella se define la función comer(), que muestra un mensaje cuando se ejecuta. La clase Perro hereda de Animal usando : Animal(), por lo que obtiene automáticamente el comportamiento definido en la clase padre sin necesidad de reescribirlo. Además, Perro agrega su propia función ladrar(), ampliando las capacidades que recibió por herencia. En resumen, este ejemplo demuestra cómo la herencia permite reutilizar código de una clase base y complementarlo con nuevas funciones en la clase hija, haciendo el programa más organizado y modular.

3. Polimorfismo

El polimorfismo permite que un mismo método pueda comportarse de diferentes maneras según el objeto que lo utilice. Esto hace posible que varias clases compartan métodos con nombres iguales, pero con comportamientos distintos. Facilita la extensibilidad y flexibilidad dentro de los programas.

Ejemplo (Kotlin):

open class Figura {
    open fun area(): Double {
        return 0.0
    }
}

class Cuadrado(val lado: Double) : Figura() {
    override fun area() = lado * lado
}

class Circulo(val radio: Double) : Figura() {
    override fun area() = 3.14 * radio * radio
}

En este ejemplo la clase Figura actúa como clase base y contiene una función area() marcada como open, permitiendo que las clases hijas la modifiquen. Esta función devuelve 0.0 por defecto. Luego, las clases Cuadrado y Circulo heredan de Figura y utilizan la palabra override para redefinir el comportamiento del método area() según cada forma: el cuadrado calcula lado * lado, mientras que el círculo usa la fórmula 3.14 * radio * radio.
Este comportamiento distinto con el mismo método es precisamente lo que representa el polimorfismo: distintas clases pueden responder de manera diferente a una misma función heredada.

4. Abstracción

La abstracción se enfoca en ocultar detalles internos de funcionamiento y mostrar solo lo esencial. Permite crear modelos simples que representan conceptos complejos del mundo real. Las clases abstractas y las interfaces son herramientas claves para lograr este principio en la POO.

Ejemplo (Kotlin):

abstract class Vehiculo {
    abstract fun encender()
}

class Auto : Vehiculo() {
    override fun encender() {
        println("El auto está encendido")
    }
}

En este ejemplo la clase Vehiculo se declara como abstract, lo que significa que no puede ser instanciada directamente y que sirve como un modelo general para otros tipos de vehículos. Dentro de ella se define la función encender() también como abstracta, lo que indica que no tiene implementación y que cada clase hija estará obligada a proporcionarla. Luego, la clase Auto hereda de Vehiculo y usa override para implementar su propia versión del método, mostrando un mensaje en pantalla cuando se ejecuta.
Este comportamiento se relaciona directamente con la abstracción, ya que se ocultan los detalles generales en una clase base y se deja que cada clase hija defina su funcionamiento específico.

¿Qué son las Clases y los Objetos?

Las clases son estructuras que definen cómo será un objeto: qué datos tendrá (atributos) y qué acciones podrá realizar (métodos). Un objeto es una instancia creada a partir de una clase, es decir, una representación real que se puede usar dentro del programa. Mientras la clase es un molde, el objeto es el resultado que podemos utilizar.

Ejemplo (Kotlin):

class Coche(val marca: String, val modelo: String) {
    fun mostrarInfo() {
        println("Coche: $marca $modelo")
    }
}

val miCoche = Coche("Toyota", "Corolla")
miCoche.mostrarInfo()

En este ejemplo se define la clase Coche, la cual funciona como un molde que describe cómo serán sus objetos. La clase recibe dos parámetros, marca y modelo, que se convierten en atributos propios de cada coche que se cree. Dentro de la clase también encontramos la función mostrarInfo(), encargada de imprimir los datos del coche en pantalla.
Luego se crea un objeto llamado miCoche usando la clase Coche como plantilla y proporcionando valores reales: “Toyota” y “Corolla”. Este objeto ya contiene sus propias características y puede ejecutar las funciones definidas en la clase. Cuando llamamos a miCoche.mostrarInfo(), se muestra la información específica de ese objeto.
